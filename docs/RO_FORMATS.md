## Observed structure (renderer-facing facts)

1. **Date header:** `Routine Orders for DDMMYY` then the weekday name on its
   own line (190626 = Friday 19 Jun 2026 ✓).
2. **Section order:** header → Duty Personnel → timeline → Safety Matters →
   Administrative Matters → Logistic Matters → Security Matters → R&D
   Matters → Instructions → Messages and QOTD → Key events of the week.
3. **Duty Personnel:** `CDO/CDS: <RANK> <NAME IN CAPS>` then
   `COS: <RANK> <NAME IN CAPS>`. Note the label is **CDO/CDS** here, not the
   app's elsewhere-label "CDO/S".
4. **Timeline:** blocks of `HHMM` + `H` (e.g. `0600H`) or `TBC`, each
   followed by one `- item` line per activity; blank line between blocks.
   The TBC block in the sample sits BETWEEN 1100H and 1800H, not at the end.
5. **Matter sections:** each is a header line + `- ` bullet lines. Empty
   sections (Logistic Matters, Instructions in this sample) render a bare
   dash line.
6. **Messages and QOTD:** quoted message + `- <attribution>` pairs; the two
   quotes carry an extra author line before the attribution.
7. **Key events of the week:** `Mon`/`Tues`/`Wed`/`Thurs`/`Fri` (note the
   spellings) + ` - ` + comma-joined items; covers the week containing the
   RO's own date. No separator line between QOTD and this section.
8. **Separators:** ➖ runs of varying length (13/12/9+space+3), some with
   trailing spaces; several headers also carry trailing spaces.

## Owner decisions (P5.1 gate, answered 2026-07-07)

- **(l) Normalize separators and whitespace.** The renderer emits a uniform
  12-➖ separator and no trailing spaces; the sample's irregular runs are
  hand-typing artifacts, not format. Bullet characters INSIDE keyed content
  (e.g. Security Matters' `⁃`) are data and pass through untouched.
- **(m) Duty label is `CDO/CDS:` in the RO only** (the rest of the app keeps
  CDO/S). Names render `RANK FULL NAME` in caps, e.g. `COS: CPL ANG CHENG ZE`.
- **(n) Timeline = standing items + auto-inserted TP events + hand-keyed
  extras.** Owner's words verbatim: *"TP calendar event should auto-insert.
  The 0600 Roll call and TBC for LP is standard for all days. On every last
  day of the week (fridays, unless there is public holidays or otherwise
  stated)."* Reading (confirmed against the Friday sample, whose TBC block is
  `SBA, LP`): `0600H — Roll call & Breakfast` and `TBC — LP` are standing
  DAILY items; `TBC — SBA` is standing on the LAST WORKING DAY of the week
  (Friday, or earlier when Friday is a public holiday — the public_holiday
  table decides). Standing items live as S3-editable rows, so "otherwise
  stated" weeks are a data edit, not a code change.
- **(n′) TBC placement (renderer decision, deterministic):** timed blocks
  ascending by time, then ONE `TBC` block last. The sample's mid-list TBC was
  hand-placement; a derived document needs a deterministic rule. Within the
  TBC block: standing items by their position, then extras in keyed order.
- **(o) Standing vs daily:** the six Matters sections (Safety,
  Administrative, Logistic, Security, R&D, Instructions) are standing
  boilerplate, S3/admin-edited; an empty section renders a bare `-` line.
  Daily: the timeline extras and **Messages and QOTD pasted as ONE free-text
  blob** (its internal quote/attribution structure is not parsed). Weekly:
  Key events (Mon–Fri, spellings `Mon/Tues/Wed/Thurs/Fri`), covering the week
  containing the RO's date; no separator line between the messages blob and
  the key-events block. Duty Personnel is derived (CONFIRMED rows dated the
  RO's date — A9; a missing duty renders an explicit placeholder, never a
  silent blank).
